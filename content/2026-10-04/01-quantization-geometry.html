01 / ROUND

연속적인 값을 몇 개의 자리로 옮긴다

파란 점은 원래 가중치다. 노란 눈금은 저장할 수 있는 값이다.

● 원래 값 → ● 복원할 값 · 두 점 사이의 가로 거리가 반올림 오차다.

2비트라면 2² = 4개, 4비트라면 2⁴ = 16개 값을 구별한다. 저장할 때는 가까운 눈금의 번호만 적고, 계산할 때 그 번호를 실제 값으로 복원한다. 같은 범위에서 눈금 수를 늘리면 값을 더 세밀하게 표현할 수 있다.

원래 값 w → 정수 번호 q → 복원 값 ŵ = d · q + b

d는 눈금 간격, b는 시작 위치다. 이 그림은 고정 범위의 균일 양자화 예제다. 실제 형식마다 부호 표현과 배율을 구하는 방법은 다르다.

02 / GROUP

K-quants는 블록마다 자를 맞춘다

작은 값끼리, 큰 값끼리 다른 배율을 쓴다. 그 배율도 저장 공간을 차지한다.

Q4_K는 32개씩 8개 블록을 묶는다. 작은 블록마다 배율과 최솟값을 나타내는 6비트 값 두 개를 두고, 이 값들을 복원할 상위 배율 두 개를 FP16으로 저장한다. 모든 작은 블록에 완전한 배율을 따로 두는 대신 배율도 압축하는 구조다.

bpw(bits per weight)는 가중치 한 개당 저장 비트 수다. Q4_0도 배율을 포함하면 (32 × 4 + 16) ÷ 32 = 4.5 bpw다. 두 형식은 저장 비용이 같아도 블록을 표현하는 방식이 다르다. K 계열 전체가 같은 블록 크기나 최솟값 필드를 쓰는 것은 아니다.

03 / PLACE

눈금 간격도 바꿀 수 있다

눈금 16개를 같은 간격으로 놓아야 할 이유는 없다.

배경 곡선은 0 근처에 값이 몰린 가상의 분포다. IQ4_NL의 눈금 값은 실제 코드의 표를 사용했다. 균일 눈금은 같은 양 끝점을 쓰는 비교용 예제다.

가중치가 특정 구간에 몰려 있다면 그 구간에 눈금을 더 배치하는 방식이 유리할 수 있다. IQ4_NL은 비균일한 16개 대표값을 쓰며, IQ4_XS도 이 대표값과 더 세분화된 배율 구조를 사용한다. 비균일 격자의 이득은 실제 가중치 분포와 배율에 따라 달라진다.

같은 4비트 → 같은 개수의 번호
번호가 가리키는 실제 값은 달라질 수 있다.
04 / LOOK UP

여러 값을 묶어 주소 하나로 저장한다

코드북은 자주 쓸 대표 벡터를 모아 둔 표다.

00

학습용 2차원 코드북 · 대표 벡터 4개
주소에는 2비트가 필요하다.

위에서는 숫자 두 개를 각각 저장하지 않고, 가까운 대표 벡터의 주소를 저장한다. 복원할 때 같은 코드북을 찾아 숫자 두 개를 꺼낸다. 실제 IQ2_XXS는 8차원 크기 패턴을 256개 대표 패턴 중에서 선택하고, 부호와 배율을 별도로 저장한다. 그림의 2차원 예제는 이 묶음 선택 원리를 보여 준다.

IQ2_XXS · 가중치 32개 기준
패턴 주소 4 × 8 + 부호 4 × 7 + 배율 4 = 64비트
슈퍼블록까지 합치면 (8 × 64 + 16) ÷ 256 = 2.0625 bpw

주소만 보면 가중치당 1비트지만, 부호와 배율까지 포함해야 저장 비용이 나온다. 7비트 부호는 8개 부호를 독립적으로 기록하는 방식이 아니라 제한된 부호 패턴 중 하나를 선택한다. I-quants에는 이런 벡터 코드북 방식과 앞의 비균일 스칼라 방식이 있으며, 모든 IQ 형식이 같은 구조는 아니다.

05 / WEIGH

어떤 방향의 오차가 더 비쌀까?

가중치가 조금 달라져도 입력이 그 차이를 크게 증폭할 수 있다.

A

파란 점: 원본 (0.35, 0.85)
A = (0.20, 0.90), B = (0.40, 0.60)
두 후보의 저장 비용은 같다고 가정한다.

중요도가 1이면 보통의 거리로 고르므로 A가 가깝다. 첫 번째 방향의 중요도를 높이면 가로 오차가 작은 B가 유리해진다. 타원은 선택된 후보와 같은 가중 오차를 갖는 점들이다. 가로 폭이 좁아지는 것은 가로 오차를 더 엄격하게 본다는 뜻이다.

출력 y = Σ wⱼxⱼ → 출력 오차 Δy = Σ (ŵⱼ − wⱼ)xⱼ
입력 간 교차항을 무시한 근사: E[(Δy)²] ≈ Σ E[xⱼ²] · (ŵⱼ − wⱼ)²

imatrix는 캘리브레이션 입력의 활성값 제곱 통계를 모은다. 직관적으로는 큰 입력이 자주 들어오는 방향의 오차에 더 큰 비용을 매긴다. 모든 가중치의 중요도를 개별적으로 직접 측정한 표나 전체 Hessian을 저장하는 것은 아니다. 실제 최적화는 형식마다 배율·격자·코드북 선택에 이 정보를 활용한다.

대표 텍스트→모델 실행
입력 활성값 통계→imatrix→양자화 때 오차 가중

K-quants에도 imatrix를 사용할 수 있다. IQ1 계열, IQ2_XXS·XS·S, IQ3_XXS의 일반 내부 텐서는 확인한 llama.cpp 코드에서 imatrix를 요구한다. IQ3_S와 IQ4 계열은 선택 사항이다. 임베딩·출력 텐서 예외가 있고, Q2_K_S에도 필수 조건이 있으므로 실행 버전의 규칙을 확인한다.

일반 문장으로 모은 통계가 서버 로그·YAML·도구 호출 JSON을 잘 대표한다고 보장할 수는 없다. 캘리브레이션 자료는 실제 사용 입력을 반영하도록 구성하고, 평가 자료는 별도로 두어 결과를 확인한다.

06 / MIX

Q4_K_M의 모든 가중치가 4비트일까?

텐서 타입의 비트 수와 모델 전체의 평균을 구분하자.

Q4_K · 4.5 bpwQ6_K · 6.5625 bpw

비율은 텐서 개수가 아닌 가중치 개수 기준이다. 이 조절기는 두 타입만 섞는 학습용 예제이며 Q4_K_M의 실제 배치 규칙을 재현하지 않는다.

Q4_K는 텐서 저장 형식이고, Q4_K_M은 여러 텐서에 어떤 형식을 쓸지 정하는 혼합 규칙이다. S·M·L 접미는 모델 크기나 문맥 길이를 뜻하지 않는다. 더 민감한 텐서에 높은 정밀도를 배정하는 정도를 나타내며, 구체적 규칙은 기본 타입·모델 구조·구현 버전에 따라 달라진다.

모델의 저장 크기를 구할 때는 각 타입으로 저장한 가중치 수에 해당 bpw를 곱해 더한다. GGUF 메타데이터와 정렬 비용도 별도이며, 실행 시 필요한 KV 캐시와 작업 공간은 이 가중치 계산에 포함되지 않는다.

이 값은 텐서 타입 자체의 비용이다. IQ3_M처럼 혼합 규칙을 나타내는 이름에는 하나의 고정된 타입 bpw를 붙일 수 없다.

배포본을 비교할 때 연결해서 볼 것

어떤 값으로 복원하는가 → 어느 텐서에 비트를 더 주는가 → 어떤 입력으로 중요도를 구했는가 → 같은 실행 조건에서 실제 과제를 잘 푸는가.

템플릿과 생성 파라미터도 맞춰야 결과 차이를 해석할 수 있다. 이름의 “4”만으로 품질이나 속도를 단정할 수는 없다.

이해했는지 확인하기

Q4_0과 Q4_K가 모두 4.5 bpw이면 같은 형식일까? 아니다. 같은 저장 비용 안에서 블록·배율을 배치하는 방식이 다르다.

imatrix를 쓰면 반드시 더 많은 비트를 저장할까? 아니다. 같은 형식에서도 오차의 배분을 바꿀 수 있다. 형식을 섞어 비트를 더 주는 작업은 별개의 선택이다.

IQ4_XS의 4.25 bpw를 모델 파일 크기에 바로 적용할까? 모든 가중치가 그 타입일 때의 부분 계산이다. 혼합된 타입과 나머지 파일 비용을 함께 계산해야 한다.
