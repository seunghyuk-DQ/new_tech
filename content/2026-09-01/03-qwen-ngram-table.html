QWEN3.8-FLASH-NEXT / PLE

51B n-gram table은 sparse lookup 메모리다

Qwen3.8-Flash-Next의 n-gram embedding은 다음 token을 복사하는 drafter가 아니다. 짧은 local pattern으로 학습된 table을 조회하고, 그 결과로 초기 layer의 hidden representation을 보강한다.

EXACT NAME: QWEN3.8-FLASH-NEXT 20M ROWS HOST RAM OFFLOAD
Main model 125B / 6B

본체는 총 125B지만 token당 약 6B만 활성화된다. Sparse MoE 계산에 쓰는 parameter다.

N-gram embedding + 51B

2,000만 개의 bigram과 trigram row를 가진 PLE다. 매 token마다 51B 전체를 matmul하지 않는다.

MTP component + 4B

Speculative draft에 쓰는 별도 모듈이다. 51B PLE와는 역할도 실행 경로도 다르다.

01 / IDENTITY

n-gram이라는 이름만 같고 역할은 다르다

Qwen PLE, prompt lookup, MTP는 모두 n-gram이나 다음 token을 언급하지만 같은 기능이 아니다. 무엇을 저장하고 어떤 값을 내놓는지부터 구분해야 한다.

QWEN PLE 학습된 vector table

Bigram과 trigram을 hash해 51B parameter table에서 row를 찾고 hidden representation에 delta를 더한다.

PROMPT LOOKUP 앞에 나온 token을 다시 제안

현재 요청에 이미 나온 token sequence를 찾아 speculative 후보로 제안한다. 별도 가중치는 없다.

MTP 다음 token을 예측하는 모듈

Target hidden state와 draft token으로 다음 후보를 예측한다. Qwen3.8-Flash-Next에는 별도의 4B MTP가 있다.

↳

PLE에 문장이나 token 문자열을 저장하는 것은 아니다. 짧은 token pattern은 학습된 embedding row의 주소로 쓰인다. Lookup 결과는 문자열이 아니라 dense vector다.

02 / LOOKUP

51B 전체가 아니라 필요한 row만 읽는다

Qwen 모델 카드에 따르면 layer 2에는 2,000만 개의 bigram과 trigram entry가 들어간다. 주소를 token ID만으로 계산할 수 있어서 앞쪽 layer 계산과 lookup을 겹쳐 실행할 수 있다.

03 / OFFLOAD

Qwen이 공식 설명한 범위는 RAM offload까지다

Qwen은 PLE를 host memory에 두고 address를 미리 계산해 async prefetch할 수 있다고 설명한다. SSD나 NVMe를 상시 serving tier로 쓰려면 runtime이 별도로 지원해야 한다.
