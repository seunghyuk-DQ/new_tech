QWEN3.8-FLASH-NEXT / PLE

51B n-gram은 계산이 아니라 기억을 키운다

Qwen3.8-Flash-Next의 n-gram embedding은 다음 token 후보를 복사하는 drafter가 아니다. 짧은 local pattern으로 거대한 학습 table을 조회해 초기 layer의 representation을 보강하는 모델 구성요소다.

01 / IDENTITY

같은 n-gram, 다른 세 기계

팀에서 "n-gram"이라는 말을 들으면 먼저 어느 층의 기능인지 확인해야 한다. 이름은 같아도 목적·저장 위치·출력이 전부 다르다.

QWEN PLE 학습된 vector memory

bigram/trigram을 hash해 51B parameter table의 row를 lookup하고 hidden representation에 delta를 더한다.

PROMPT LOOKUP 반복 token 복사 후보

현재 request 안에서 이미 나온 token sequence를 찾아 speculative 후보로 제안한다. 가중치가 없다.

MTP 미래 token proposer

target hidden과 draft token으로 다음 후보를 예측한다. Qwen3.8-Flash-Next에는 별도 4B MTP가 있다.

↳

PLE는 "문장을 저장한 hash map"이 아니다. 짧은 token pattern이 학습된 embedding row의 주소가 될 뿐, 반환되는 것은 token 문자열이 아니라 dense vector다.

03 / OFFLOAD

RAM은 공식 설계, SSD는 최신 runtime 옵션

Qwen은 PLE를 host memory에 두고 address를 미리 계산해 async prefetch할 수 있다고 설명한다. SSD/NVMe를 상시 serving tier로 쓰는 것은 model architecture가 아니라 runtime 구현 문제다.
