01 / PIPELINE

배포할 target에서 학습 데이터를 만든다

기존 응답을 target tokenizer로 다시 나누는 것만으로는 부족하다. 실제로 배포할 target revision과 chat template, thinking mode, sampling 설정으로 응답을 다시 생성해야 한다.

01

실제 요청을 닮은 prompt를 모은다

채팅, 수학, 코드, tool use, 한국어 요청의 실제 비율을 반영한다. 평가는 별도의 hold-out set으로 한다.

02

배포할 target으로 응답을 다시 만든다

Target이 실제로 고른 continuation이 on-policy 학습 데이터다. 모델, tokenizer, template, thinking contract를 모두 고정한다.

03

hidden state와 logits를 추출한다

EAGLE-3는 target의 여러 layer hidden state를 쓴다. DFlash 계열에는 block 조건을 만들 target feature가 필요하고, KL loss를 쓰려면 target logits도 저장해야 한다.

04

작은 speculator만 학습한다

Target은 동결한다. Native MTP는 호환 MTP layer가 들어 있는 checkpoint에서 head만 fine-tune한 뒤 본체에 다시 붙인다.

05

실제 serving 속도로 판단한다

Training loss만 봐서는 부족하다. 위치별 acceptance, mean accepted length, draft latency, VRAM, 같은 workload의 end-to-end tok/s를 함께 측정한다.

↳

결과를 보존하는 책임은 drafter가 아니라 verifier에 있다. Drafter가 좋아지면 acceptance와 속도는 올라간다. 그래도 최종 target 분포를 지키는 장치는 verifier의 rejection sampling과 교정 절차다.

02 / DATA

응답뿐 아니라 hidden state도 저장한다

Prompt와 target response만 저장해서는 target-conditioned drafter를 학습할 수 없다. Token 위치마다 hidden tensor가 필요하며 데이터가 많아지면 저장공간이 빠르게 커진다.

03 / MODES

GPU가 적으면 시간을 나눈다

Online 학습은 target server와 trainer를 동시에 띄운다. Offline 학습은 target inference와 drafter training을 차례로 실행해 같은 GPU를 재사용하지만 SSD 공간이 많이 든다.

ONLINEGPU는 더 쓰고 disk는 아낀다

hidden state를 실행 중에 만들고 바로 버린다. Target serving GPU와 training GPU가 동시에 필요하다.

OFFLINEGPU를 재사용하고 disk에 저장한다

hidden state를 먼저 만들어 저장한다. Target을 내린 뒤에는 모든 GPU를 drafter 학습에 쓸 수 있다.

HYBRID첫 epoch에서 cache를 만든다

첫 epoch에는 생성 비용이 들지만 다음 epoch부터 cache를 재사용한다. 초기 peak memory와 cache 용량을 모두 잡아야 한다.

04 / GPU

GPU 수는 target과 학습 방식에 따라 달라진다

공개 tutorial의 GPU 수를 최소 사양으로 받아들이면 안 된다. Target 크기, context, 추출할 layer, draft layer 수, precision, 데이터량에 따라 필요한 자원이 달라진다.
