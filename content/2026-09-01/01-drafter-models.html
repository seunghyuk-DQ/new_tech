01 / CONTRACT

Target을 한 번 호출해 여러 토큰을 검증한다

일반적인 autoregressive decoding은 토큰을 하나 만들 때마다 target을 호출한다. Speculative decoding은 가벼운 proposer가 후보를 먼저 만들고, target이 한 번의 pass로 여러 위치를 검증한다.

한 speculative round LEFT-TO-RIGHT ACCEPTANCE

후보 N개 제안
d1d2d3d4

작은 LM · MTP · EAGLE · DFlash · lookup

→
02 · target verifier
한 pass로 N 위치 검사
✓✓✕–

처음 틀린 위치 이후의 후보는 버리고, 그 위치에는 target token을 넣는다

→
03 · commit
2 draft + 1 target
d1d2t3

검증이 끝나도 target의 greedy output이나 sampling distribution은 바뀌지 않는다

↳

Acceptance가 높다고 반드시 빠른 건 아니다. Target decode에서 아낀 시간이 draft, verify, 메모리 비용보다 커야 한다. 따라서 mean accepted length뿐 아니라 draft latency, VRAM, end-to-end throughput도 함께 본다.

02 / TAXONOMY

후보를 만드는 여섯 가지 방식

Target 정보를 얼마나 쓰는지, block 안의 token이 서로 영향을 주는지를 기준으로 나누면 다음 여섯 가지다.

MODEL-INTEGRATED

Native / Gemma MTP

SEQUENTIAL
입력target hidden state와 현재 draft token. Gemma assistant는 target activation과 KV cache를 공유한다.
강점target에 맞춰져 있어 acceptance가 높다. Native MTP는 추가 checkpoint도 필요 없다.
약점N이 커지면 MTP path도 반복해서 실행한다. Native head가 없는 모델에는 바로 붙일 수 없다.
TARGET-CONDITIONED

EAGLE-3

SEQUENTIAL
입력target의 앞·중간·뒤 layer hidden state를 합치고 직전에 뽑은 token embedding을 더한다.
강점앞에서 뽑은 token이 다음 후보에 직접 영향을 주므로 문장이 덜 어긋난다.
약점후보마다 작은 decoder를 차례로 실행한다. Proposal이 길수록 draft latency가 누적된다.
BLOCK DIFFUSION

DFlash

PARALLEL
입력확정된 anchor와 mask block. Target hidden state는 각 draft layer의 추가 K/V로 쓴다.
강점미래의 모든 위치를 한 번의 forward pass에서 예측해 긴 block의 draft 비용을 낮춘다.
약점뒤쪽 위치는 같은 pass에서 실제로 선택된 앞 token을 볼 수 없다. 각각은 맞아도 이어 놓으면 어색할 수 있다.
PARALLEL + CORRECTION

DSpark

HYBRID
입력DFlash base logits에 직전 선택 token으로 계산한 가벼운 Markov bias를 더한다.
강점backbone은 한 번만 실행한다. 그 뒤 작은 순차 head가 block 안의 token 관계를 보정한다.
주의설계에는 confidence prefix selection이 있지만 AMD/vLLM 보고서의 실험에서는 꺼져 있었다.
TOP-K PATH

DFlash 2

PREVIEW
입력각 위치의 top-K 후보, 인접 후보의 transition score, local dynamic convolution을 쓴다.
강점top-1이 틀려도 정답이 top-K 안에 남아 있다면 더 일관된 경로를 다시 고를 수 있다.
주의공개 checkpoint와 PR build를 기준으로 한 최신 기능이다. Stable vLLM의 지원 여부는 따로 확인해야 한다.
NO TRAINING

Prompt n-gram

LOOKUP
입력현재 요청의 prompt나 accepted context에 이미 나온 token sequence를 찾는다.
강점가중치와 추가 model KV가 없다. 코드 수정, 복사, 반복 문장이 많은 작업에서는 비용이 거의 들지 않는다.
약점처음 보는 문장에는 제안할 후보가 없다. Qwen의 51B PLE n-gram table과는 전혀 다른 기능이다.
03 / DECISION

Acceptance보다 실제 병목을 먼저 본다

Batch가 작고 target decode가 비싸면 병렬 drafter가 유리하다. 반대로 요청이 몰리면 verifier의 batching 효율이 이미 높아서 speculative decoding의 추가 비용이 이득을 없앨 수 있다.

방법추가 checkpoint후보 생성잘 맞는 상황운영 위험
작은 AR LM필요순차target 변경이 어렵고 독립 drafter를 구하기 쉬울 때별도 weight와 KV가 필요하다. Target과 분포가 다르면 acceptance가 낮다.
Native MTP없음순차checkpoint에 MTP가 내장된 Qwen 계열N 증가 시 순차 비용, 지원 아키텍처 한정
Gemma MTP필요순차공식 target-assistant pair가 있을 때정확한 target revision pairing 필요
EAGLE-3필요순차성숙한 target-conditioned baseline이 필요할 때긴 proposal의 draft latency
DFlash / DSpark필요병렬 / hybrid긴 block, 낮은 concurrency, target decode가 비쌀 때고정 block 학습, runtime·GPU별 지원 차이
DFlash 2필요병렬 + pathtop-K recall은 높지만 top-1 coherence가 약할 때최신 main branch에 의존하며 실서비스 검증이 부족하다.
Prompt n-gram없음lookup코드 agent·편집·반복 출력새 continuation에는 효과가 거의 없음
