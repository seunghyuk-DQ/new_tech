01 / CONTRACT

큰 모델의 한 번을 넓게 쓴다

표준 autoregressive decode는 target을 한 토큰마다 다시 호출한다. speculative decoding은 가벼운 proposer가 미래 후보를 먼저 만들고, target의 한 번의 넓은 pass로 여러 위치를 검증한다.

한 speculative round LEFT-TO-RIGHT ACCEPTANCE

후보 N개 제안

작은 LM · MTP · EAGLE · DFlash · lookup

→
02 · target verifier
한 pass로 N 위치 검사
✓✓✕–

첫 reject 뒤 후보는 폐기, reject 위치는 target token으로 교체

→
03 · commit
2 draft + 1 target
d1d2t3

검증이 올바르면 target의 greedy output 또는 sampling distribution을 보존

↳

"acceptance가 높다 = 빠르다"는 아니다. 실제 이득은 절약한 target decode 비용이 draft·verify·메모리 비용보다 클 때 생긴다. 그래서 mean accepted length, draft latency, VRAM, end-to-end throughput을 같이 본다.

02 / TAXONOMY

후보를 만드는 여섯 가지 방식

target 정보 사용 여부와 block 내부 의존성을 기준으로 보면, 사용자의 MTP → DFlash → DSpark → DFlash2 설명은 큰 방향에서 맞다.

MODEL-INTEGRATED

Native / Gemma MTP

SEQUENTIAL
입력target hidden + 현재 draft token. Gemma assistant는 target activation/KV를 공유.
강점target에 밀착되어 acceptance가 높고 native MTP는 추가 checkpoint가 없다.
약점N이 늘면 MTP path도 반복 실행된다. native head가 없는 모델에는 바로 붙일 수 없다.
TARGET-CONDITIONED

EAGLE-3

SEQUENTIAL
입력target early·middle·late hidden states를 융합하고 sampled-token embedding을 결합.
강점앞에서 뽑힌 token이 다음 draft에 직접 영향을 줘 문장 일관성이 좋다.
약점후보마다 작은 decoder를 순차 실행하므로 긴 proposal에서 draft latency가 누적된다.
BLOCK DIFFUSION

DFlash

PARALLEL
입력확정 anchor + mask block. target hidden을 각 draft layer의 추가 K/V로 사용.
강점모든 미래 위치를 한 forward에서 예측해 긴 block의 draft 비용을 낮춘다.
약점후반 위치가 같은 pass에서 실제 선택된 앞 token을 보지 못해 조합이 어색해질 수 있다.
PARALLEL + CORRECTION

DSpark

HYBRID
입력DFlash base logits + 직전 선택 token에서 만든 저비용 Markov bias.
강점backbone은 한 번만 돌리고 작은 순차 head로 block 내부 의존성을 보정한다.
주의confidence prefix selection은 설계에 있지만, AMD/vLLM 보고서의 실험 경로에서는 비활성이었다.
TOP-K PATH

DFlash 2

PREVIEW
입력각 위치의 top-K 후보 전체 + 인접 후보 transition score + local dynamic convolution.
강점top-1이 틀려도 top-K 안의 더 일관된 경로를 선택한다. 사용자 설명의 핵심이 정확하다.
주의공개 checkpoint·PR build 기준의 최신 기능이다. 설치된 stable vLLM 지원을 별도 확인해야 한다.
NO TRAINING

Prompt n-gram

LOOKUP
입력현재 request의 prompt/accepted context 안에 이미 나온 token sequence.
강점가중치와 추가 model KV가 없다. 코드 수정·복사·반복 텍스트에 특히 싸다.
약점새로운 문장에는 후보가 없다. Qwen의 51B PLE n-gram table과는 완전히 다른 기능이다.
03 / DECISION

선택은 acceptance가 아니라 병목에서

작은 batch와 비싼 target decode에서는 병렬 drafter의 장점이 크게 보인다. 높은 concurrency에서는 verifier가 이미 효율적으로 batching되어 speculative overhead가 이득을 상쇄할 수 있다.

방법추가 checkpoint후보 생성잘 맞는 상황운영 위험
작은 AR LM필요순차target 변경이 어렵고 독립 draft model을 쉽게 구할 때별도 weight/KV, target과 분포가 다르면 낮은 acceptance
Native MTP없음순차checkpoint에 MTP가 내장된 Qwen 계열N 증가 시 순차 비용, 지원 아키텍처 한정
Gemma MTP필요순차공식 target-assistant pair가 있을 때정확한 target revision pairing 필요
EAGLE-3필요순차성숙한 target-conditioned baseline이 필요할 때긴 proposal의 draft latency
DFlash / DSpark필요병렬 / hybrid긴 block, 낮은 concurrency, target decode가 비쌀 때고정 block 학습, runtime·GPU별 지원 차이
DFlash 2필요병렬 + pathtop-K recall은 높지만 top-1 coherence가 약할 때preview/main-only 경계, production 검증 부족
Prompt n-gram없음lookup코드 agent·편집·반복 출력새 continuation에는 효과가 거의 없음
