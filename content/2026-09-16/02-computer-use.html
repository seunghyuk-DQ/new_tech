Computer Use 작동법 이해하기

모델이 화면을 보고 다음 행동을 정하면, 실행기가 클릭·드래그·입력을 수행한다. 바뀐 화면을 다시 확인하고 필요한 행동을 이어 간다. 화면 관찰 → 판단 → 실행 → 재확인이 작업이 끝날 때까지 반복된다.

01 / LOOP

모델은 판단하고, 실행기는 앱을 조작한다

화면 관찰

실행기가 현재 화면을 캡처한다.
모델은 사용자 요청과 화면, 사용할 수 있는 도구 정의를 함께 읽는다.

→
다음 행동 결정

버튼·캔버스 위치와 현재 상태를 파악한다.
클릭, 드래그, 입력 또는 코드 실행을 선택한다.

→
실행 후 재확인

실행기가 도구 호출을 실제 동작으로 옮긴다.
새 화면을 모델에 돌려주고 성공 여부를 판단한다.

예를 들어 “tldraw에서 마우스로 원숭이를 그려줘”라는 요청을 받으면, 모델은 캔버스와 Draw 도구를 찾고 머리·귀·눈·입 등으로 작업을 나눈다. 실행기는 선택된 위치를 클릭하고 각 선의 경로를 따라 마우스를 움직인다. 선이 빠졌다면 모델이 다음 캡처에서 확인해 보정한다.

화면 속 버튼과 호출 가능한 도구는 서로 다른 정보다. Draw 버튼은 화면이나 접근성 정보에서 찾는 앱의 요소다. click, drag, screenshot 같은 도구의 이름과 인자는 실행 환경이 모델에 제공한다. 화면에서 도구 API 목록을 알아내는 것은 아니다.

행동은 구조화된 도구 호출로 전달할 수도 있고, 여러 호출을 묶은 스크립트로 전달할 수도 있다. 매번 전체 스크립트를 새로 만드는 것이 필수는 아니다. 짧은 행동 묶음 뒤에 화면을 확인하면 앞선 오동작에 맞춰 다음 행동을 바꿀 수 있다.

동작 원리: OpenAI Computer use 가이드. API의 관찰·실행 루프를 설명한 것으로, Codex 플러그인의 비공개 내부 호출을 재현한 로그는 아니다.

Codex의 Computer Use는 앱에 연결된 플러그인으로 동작한다. 공개 문서만으로 플러그인 전체의 소스 공개 여부와 내부 구현을 확정하기는 어려우므로, 여기서는 확인 가능한 사용 방식과 실행 흐름을 중심으로 설명한다.

Cua는 computer-use를 위한 오픈소스 프로젝트다. Cua MCP는 모델 자체가 아니라 agent가 컴퓨터를 제어할 수 있도록 도구를 연결하는 계층이다. “아무 하네스에 연결”은 MCP 연결과 필요한 도구·이미지 처리를 지원하는 실행 환경에 연결한다는 뜻으로 이해하면 된다. OS와 드라이버 지원, 실행 권한도 맞아야 한다.

03 / SEQUENCE

tldraw에서 원숭이를 그리는 순서

아래는 GPT-6 Astra를 사용하는 예시 흐름이다. 실제 호출 이름과 캡처 간격은 실행 환경에 따라 달라진다. drag(path)는 경로를 따라 마우스를 누르고 이동한 뒤 놓는 동작을 뜻한다.

순서보내는 쪽 → 받는 쪽요청 또는 반환
1사용자 → 모델“tldraw에서 마우스로 원숭이를 그려줘”
2모델 → 실행기 → tldraw현재 화면 캡처 요청
3실행기 → 모델빈 캔버스와 툴바가 보이는 스크린샷 반환
4모델 내부 판단캔버스·Draw 도구 위치 파악, 원숭이를 여러 stroke로 분해
5모델 → 실행기 → tldrawclick(x, y)로 Draw 도구 선택
6모델 → 실행기 → tldrawdrag(path): 머리 윤곽 → 왼쪽 귀 → 오른쪽 귀
7모델 → 실행기 → tldrawdrag(path): 왼쪽 눈 → 오른쪽 눈 → 입과 코
8모델 → 실행기 → tldraw요청한 그림에 맞춰 몸통·팔·꼬리 stroke 추가
9실행기 → 모델실행 후 스크린샷 반환. 필요하면 중간 단계에서도 캡처
10모델 내부 판단모양과 누락된 선 확인
11A모델 → 사용자정상적으로 완성됐으면 결과 전달
11B모델 → 실행기 → 모델누락된 선 보정 → 새 스크린샷 확인 → 결과 전달 
한 stroke의 실행
mouse_down(시작점)
mouse_move(경로의 다음 점)  // 경로를 따라 반복
mouse_up(끝점)

다음 확인
screenshot → 모델의 결과 판단 → 다음 stroke 또는 완료

마우스 이동 점마다 모델이 다시 추론할 필요는 없다. 모델이 만든 하나의 경로를 실행기가 여러 이동 이벤트로 수행할 수 있다.

05 / POLYGON

폴리곤 라벨링에 적용하면

작은 벌레처럼 경계가 복잡한 대상을 라벨링하려면, agent가 사용할 이미지 뷰어와 폴리곤 편집 도구를 준비할 수 있다. 다음은 사용자가 언급한 작업을 바탕으로 구성한 구현 아이디어다. 특정 X 게시물의 실제 구현을 확인한 설명은 아니다.

이미지 확인 → 확대

대상을 찾고 경계가 잘 보이는 배율로 조정한다.
확대·이동 후 화면과 좌표 변환 정보를 다시 읽는다.

→
정점 계산 → 적용

모델이 경계를 따라 폴리곤 좌표를 구성한다.
마우스로 정점을 찍거나, 준비된 도구에 좌표 배열을 전달한다.

→
오버레이 확인 → 수정

이미지 위에 폴리곤을 표시한다.
경계 이탈·누락을 확인해 정점을 수정하고 반복한다.

준비할 도구의 예agent가 하는 일
이미지 열기 / 현재 상태 조회이미지 크기·뷰포트·배율을 확인한다.
확대·축소 / 화면 이동작은 경계나 가려진 부분을 자세히 본다.
폴리곤 추가 / 정점 수정 / 되돌리기좌표 배열을 적용하거나 오동작을 수정한다.
오버레이 캡처 / 결과 저장원본 위의 경계를 확인하고 라벨을 저장한다. 
// 아래 이름은 설계 예시이며 실제 Cua API가 아니다.
view = inspect_image()
zoom_to(target_region)
view = inspect_image()          // 변경된 화면·배율·원점 확인
points = model_plan_polygon(view)
apply_polygon(points, coordinate_space="image")
preview = capture_overlay()
// 모델이 preview를 확인하고 수정하거나 저장한다.

확대·축소 후에는 화면 좌표와 원본 이미지 좌표를 구분해야 한다. 화면에서 찍은 점을 그대로 원본 좌표로 저장하면 배율이나 pan 위치가 바뀔 때 폴리곤이 어긋난다. 앱이 제공하는 좌표 변환을 사용하고, 최종 라벨은 원본 이미지 기준으로 저장하는 편이 명확하다.

이 방식은 모델이 경계를 판단하고 도구가 편집을 수행하는 반복 작업이다. 별도의 detection·segmentation 모델을 연결하면 초기 후보를 만들 수 있지만, Computer Use나 MCP를 붙였다는 이유만으로 경계 추정 모델이 생기는 것은 아니다.

06 / TAKEAWAYS

작동 방식을 이해할 때 볼 세 가지

  • 모델: 화면을 해석하고 다음 동작·좌표·완료 여부를 판단한다.
  • 실행 환경: 사용할 도구와 상태를 모델에 전달하고 실행 결과를 돌려준다.
  • 제어 도구: 마우스·키보드·스크린샷 또는 앱의 구조화된 편집 기능을 실제로 수행한다.

잘 맞는 도구를 준비할수록 모델은 반복적인 입력보다 대상 판단과 결과 확인에 집중할 수 있다. 폴리곤 좌표를 한 번에 받는 편집 도구가 있다면, 정점마다 클릭하는 작업을 좌표 배열 전달로 줄일 수 있다.
