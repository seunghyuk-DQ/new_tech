LOCATEANYTHING / PARALLEL BOX DECODING

LocateAnything의 NTP + MTP 공동 학습

MoonViT 400M과 Qwen2.5 3B를 연결하고, 박스 단위 MTP를 NTP와 함께 학습한다. 적용할 핵심은 구조에 맞춘 토큰 블록과 순차 추론 성능까지 개선한 보조 학습 신호다.

MoonViT는 Kimi 계열에서 사용하는 비전 인코더다. Native-resolution 처리는 작은 물체에 필요한 세부 공간 정보를 보존하는 데 유리하다. 다만 LocateAnything의 성능 향상을 비전 인코더 하나의 효과로 해석할 수는 없다.

PBD(Parallel Box Decoding)는 박스 토큰을 생성하는 방식이다. 완성된 출력 뒤에 좌표를 다시 예측하는 별도 모델이 아니라, 같은 디코더의 출력 과정에 적용된다.

02 / BLOCKS

박스 하나를 길이 6의 블록으로 묶는다

t = <ref>label</ref>
b = <box><x1><y1><x2><y2></box>

box block = 시작 토큰 1 + 좌표 토큰 4 + 종료 토큰 1 = 6

좌표는 0~1000 범위로 정규화한 전용 토큰이다. 위 표기는 논문의 개념 표현이며 문자열의 글자 수를 세는 것이 아니다. Label은 별도의 semantic block으로 표현한다. 빈 칸은 <null>로 채우고, 긴 label은 여러 블록으로 나눈다.

Block-causal attention은 블록 사이에 순서를 유지하고 같은 블록 안에는 양방향 attention을 허용한다. 박스마다 네 좌표와 구조 토큰을 함께 예측하므로 임의의 토큰 길이로 잘라 서로 다른 박스의 일부를 한 블록에 섞는 문제를 줄인다.

03 / TRAINING

공동 학습은 detection·grounding 단계에 적용한다

전체 파이프라인학습 내용NTP + MTP
Stage 1Caption 중심 base VLM 학습일반 NTP-style
Stage 2General VQA, OCR, 수학, 과학 등 능력 확장일반 NTP-style
Stage 3LocateAnything detection / grounding 학습Joint training
Stage 4Dense detection 강화Joint training

논문 본문에서 detection·grounding의 두 단계를 Stage-1 / Stage-2라고 부르는 부분은 전체 파이프라인의 Stage 3 / Stage 4에 해당한다. Stage 1은 MLP만 학습하고, Stage 2–4는 전체 구성 요소를 학습한다.

04 / LOSS

같은 정답을 두 표현으로 학습한다

Mermaid 원문 보기
flowchart LR
    GT["같은 정답<br/>class + box + 좌표"] --> NTP["NTP 표현<br/>이전 토큰을 하나씩 입력"]
    GT --> MTP["MTP 표현<br/>anchor + [mask] block"]
    C["이미지 + query<br/>공유 context"] --> F["한 번의 Transformer forward<br/>custom attention mask"]
    NTP --> F
    MTP --> F
    F --> LN["NTP logits"]
    F --> LM["MTP logits"]
    LN --> CN["NTP Cross-Entropy"]
    LM --> CM["MTP Cross-Entropy"]
    CN --> SUM["L = L_NTP + λ · L_MTP"]
    CM --> SUM
    SUM --> BP["공유된 MoonViT / projector / Qwen에 backprop"]

일반화하면 L = L_NTP + λ · L_MTP로 쓸 수 있지만, 논문의 목적함수는 별도 가중치 없이 두 손실을 더한다. NTP는 next-token prediction, MTP는 multi-token prediction이다.

NTP 경로는 causal attention을 사용한다. MTP는 공유 context, 현재 블록보다 앞선 토큰 정보, 같은 블록 내부의 masked 표현을 참조한다. 현재 예측할 박스의 정답 좌표를 미리 보여주는 것은 아니다. 참조 가능한 prefix의 경계를 attention mask로 제한해 정답 누출을 막는다.

Attention mask 그림 읽기

  1. 회색 C — 공유 context. 이미지와 query는 두 학습 표현이 함께 사용하는 입력이다.
  2. 파란 N — NTP. 이전 토큰으로 다음 정답 토큰을 맞춘다. 삼각형 모양은 뒤쪽의 미래 토큰을 볼 수 없다는 뜻이며, 오른쪽 MTP 입력도 참조하지 않는다.
  3. 노란 B₁·B₂ — MTP. 각 6칸 블록 안에서는 모든 위치가 서로의 표현을 참조한다. B₁은 label, B₂는 box를 예측하는 예시다. 서로 다른 블록을 한 덩어리로 묶지 않는다.
  4. B₂ 왼쪽의 파란 영역 — 앞선 prefix. box를 예측할 때 이미 앞에 있는 label 정보는 사용할 수 있다. 이 영역은 현재 box의 정답 좌표를 읽도록 허용한 것이 아니다.
  5. 왼쪽 Target과 Input — 입력과 정답의 구분. 노란 입력의 좌표 위치는 모두 mask이고, 실제 좌표 정답은 loss 계산에 사용한다.
그림의 semantic block B₁ (6개 출력)
입력: Query   [mask] [mask] [mask] [mask] [mask]
정답: <ref>   hot    dog    </ref> <null> <null>

그림의 box block B₂ (6개 출력)
입력: </ref> [mask] [mask] [mask] [mask] [mask]
정답: <box>  <313>  <638>  <345>  <663>  </box>

첫 입력은 예측을 시작할 anchor다. 그림의 box 블록에서는 앞선 label의 종료 토큰 </ref>가 anchor이고, <box>부터 종료 토큰까지 6개가 예측 대상이다. “좌표들이 서로 참고한다”는 말은 masked 위치의 표현이 상호작용한다는 뜻이다.

Slow 모드에서 공동 학습은 F1을 50.1 → 52.1 (+2.0점)로 높였다. 이 실험은 MTP 손실의 이점이 병렬 추론 속도에만 한정되지 않음을 보여준다.

표는 논문 보고값이다. 다른 데이터·backbone에서 같은 개선 폭이 나오는지는 별도로 평가해야 한다.

06 / OUTPUT

출력 형식이 같아도 label의 의미는 task에 따라 다르다

Task개념적 출력의미
Object detection<ref>dog</ref><box>…</box>이 위치에 개라는 객체가 있다.
OCR / text spotting<ref>dog</ref><box>…</box>이 박스 안에 실제로 “dog”라는 글자가 쓰여 있다.

Query와 학습 task가 label의 의미를 결정한다. Detection의 클래스 이름과 OCR의 인식 문자열은 같은 문자열이어도 서로 다른 정답이다.

07 / APPLICATION

구조 학습과 출력 검증을 함께 적용한다

요소역할
Attention mask같은 박스 내부의 masked 위치들이 표현을 교환한다.
MTP loss네 좌표와 구조 토큰을 같은 블록의 정답으로 함께 학습한다.
Box-aligned block서로 다른 박스의 좌표가 하나의 블록에 섞이지 않도록 경계를 맞춘다.
Hybrid fallback병렬 출력의 형식 오류·공간적 불확실성에 해당하는 블록을 NTP로 재생성한다.
적용 시 후처리좌표 순서·범위·파싱 성공 여부를 명시적으로 검사한다. 
유효한 2D bounding box의 필수조건
x1 < x2
y1 < y2

AR(NTP)로 생성해도 박스 형식과 기하 조건이 자동으로 보장되지는 않는다. MTP 공동 학습 역시 이 부등식을 강제로 만족시키는 수학적 제약은 아니다. 파싱 실패율과 잘못된 박스 비율을 정확도·처리량과 함께 확인해야 한다.

공식 Hybrid와 적용 제안을 구분한다. 논문은 형식 검사와 좌표 확률·후보 분산을 이용한 재생성을 설명한다. 공개 코드의 형식 검사만으로 x1 < x2, y1 < y2까지 보장된다고 쓰면 안 된다. 이 조건은 적용 파이프라인의 별도 검증 항목으로 둔다.

구현 참고: 논문의 불확실성 기준은 top-1 확률 0.7 미만 및 top-5 좌표 범위 80 초과다. 확인한 공개 revision의 decode_bbox_avg에는 0.9 / 60 기준이 활성화되어 있어 논문 설정과 구분해야 한다.

적용할 핵심: 박스 경계에 맞춘 길이 6의 토큰 블록을 만들고 NTP와 MTP를 공동 학습한다. Slow 모드에서도 F1이 개선됐으므로, 병렬 추론을 도입하기 전부터 학습 손실의 효과를 따로 확인할 수 있다.

적용 실험에서는 기존 NTP-only를 기준으로 공동 학습 + Slow를 먼저 비교하고, 이후 Fast·Hybrid의 속도와 정확도를 평가한다. 단순히 프롬프트에 박스 형식을 추가하는 것만으로 PBD가 구현되지는 않는다. 토큰 구성, 학습용 attention mask, 손실, 추론 루프를 함께 맞춰야 한다.
